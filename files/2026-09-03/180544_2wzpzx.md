## 改动 1：广告元数据查询能力扩展（AdMetaQuery）

**目标**：支持账户级扫描（advertiserId 过滤）+ 三阶段筛选所需过滤字段包。
**需要新增筛选，参考后台广告列表**

```thrift
// 文件：otdapi_service.thrift（既有，扩展）
struct AdMetaQuery {
    1: optional list<string> campaignIds,      // 【已有】计划ID批量（精确）
    2: optional list<string> adIds,            // 【已有】广告ID批量（精确）
    3: optional string adTitle,                // 【已有】广告名称（精确匹配）
    4: optional list<i32> deliveryChannelCodeList,  // 【已有】渠道过滤
    5: optional string advertiserId,           // 【已有字段】广告主ID——当前 SDK 已含，
                                               // 【需求】请确认/支持按此字段过滤返回该广告主名下全部广告（账户级扫描入口）
    6: optional string dt,                     // 【已有】离线日期（快照查询用）
    7: optional string hour,                   // 【已有】离线小时（快照查询用；待改 hours 见改动 1b）
    8: optional PageOTDModel page,             // 【已有】分页

    // ===== 以下为【新增】过滤字段包（账户级扫描用） =====
    10: optional string createTimeStart,       // 【新增】创建时间起（yyyy-MM-dd HH:mm:ss 或 yyyy-MM-dd，含端点）
    11: optional string createTimeEnd,         // 【新增】创建时间止（含端点）——用途：扫描时过滤上线天数≥7天的广告
    12: optional list<i32> adStatusList,       // 【新增】广告状态过滤（1=启用/2=停用/3=删除）——STEP2 状态硬拦截前置
    13: optional list<i32> marketingSceneList, // 【新增】TMAX 营销场景过滤（1=日常销售/2=新品成长/3=商品打爆智能拓量/4=活动引流/5=直播预热）——广告维度筛选
    14: optional list<i32> ocpcStageList,      // 【新增】oCPX 投放阶段过滤——依赖改动 4 的字段暴露；
                                               // 枚举以下游定义为准（如 1=一阶段/2=二阶段），STEP2 单品广告"已进入二阶段"前置过滤
                                              
                                             
}
```

**配套说明**：
- 双模语义（写入接口文档）：**详情模式**=adIds/adTitle（精确锁定少量实体）；**扫描模式**=advertiserId+过滤器包（账户级批量）；两模式共用 `AdMetaModel` 返回结构；
- 扫描模式返回量受分页约束（单页最大 20，调用方翻页拉全）；
- 过滤器均为可选，缺省不过滤（与既有字段行为一致）。

## 改动 2：广告效果报表扩展 ROI 指标分子（结构化指标设计）

**目标**：报表返回中随 impressions/cost 并列携带 ROI 指标分子映射（ROI=分子÷花费由调用方自算）。

**核心口径（已拍板）**：**数据圈选窗口恒为近 7 天**（PRD 固定"最近 7 个完整自然日"）；指标中的"24 小时/14 天"是**归因窗口**（转化回溯期，下游指标处理），**不是数据圈选天数**——归因窗口与数据圈选解耦：下游按指标归因聚合分子，调用方按近 7 天圈选分母（消耗）自算 ROI。

**新增自定义指标参数返回**

```thrift
// 文件：otdapi_service.thrift（既有，扩展）
struct OtdReportQuery {  // 效果报表查询（OtdAdReportQuery/OtdCampaignReportQuery 同构扩展）
    // ===== 既有字段（略）：advertiserId/adId(campaignId)/startDate/endDate（调用方固定传近 7 个完整自然日）=====

    // ===== 【新增】自定义指标口径选择 =====
    6: optional list<string> customMetrics,  // 自定义指标 hardCode 列表（枚举见下，8 项闭集）；
                                              // 指定后 roiSalesMap 仅含所选指标；缺省返回全量 8 项（兼容）
}

// ===== ROI 指标枚举（hardCode，8 项闭集）=====
// 归因窗口(24h/14d) × 转化事件(下单 order/成交 deal) × 归因对象(商家 merchant/商品 goods)
// ROI_24H_ORDER_MERCHANT / ROI_24H_ORDER_GOODS / ROI_24H_DEAL_MERCHANT / ROI_24H_DEAL_GOODS
// ROI_14D_ORDER_MERCHANT / ROI_14D_ORDER_GOODS / ROI_14D_DEAL_MERCHANT / ROI_14D_DEAL_GOODS

struct OtdReportItem {
    // ===== 既有字段（略）：impression/click/cost/ctr/cpc/cpm/dt/hm =====

    // ===== 【新增】指标分子映射（分天粒度） =====
    20: optional map<string, double> roiSalesMap,  // key=指标 hardCode（如上枚举），value=该归因口径销售额——
                                                    // 按 item 的 dt/hm 分天粒度返回（7 天内逐日数据）；
                                                    // 某指标无数据时该 key 缺省——不得置 0
                                                    // （调用方按该指标判定时该广告直接淘汰）
}
```

**配套说明**：
- **缺失语义**：`roiSalesMap` 中某指标 key 缺省=该口径无数据（不得返回 0）——调用方按"数据缺失"处理（该广告 ROI 无法自算→淘汰）；
- 前端交互（已定）：用户手动单选一个指标（或不选按渠道推荐默认），固定问题格式如"按 14 天成交 ROI（商品）看看唯直达有哪些广告存在较大放量空间"——调用方解析指标 hardCode（14 天成交 ROI（商品）→`ROI_14D_DEAL_GOODS`）后传入 `customMetrics`；
- 归因窗口枚举值定义（24h/14d 的精确回溯口径）请在 IDL 注释中给出；
- 历史分天（offline）报表需扩展（ROI 判定用历史分天数据；实时分时本场景不用）。

## 改动 3：广告主维度分渠道效果聚合接口（新增）

**目标**：渠道门槛=该渠道近 7 天总销售额÷总花费（ROI 同口径），避免调用方拉全量自聚合。
**注意分页**

```thrift
// 文件：otdapi_service.thrift（新增接口）
struct AdvertiserChannelReportQuery {
    1: required string advertiserId,           // 广告主ID
    2: required i32 deliveryChannelCode,       // 渠道（99=唯智展/103=唯触点/104=唯直达/106=TMAX）
    3: required string startDt,                // 开始日期 yyyyMMdd（含）
    4: required string endDt,                  // 结束日期 yyyyMMdd（含；周期≤7 天）
}

struct AdvertiserChannelReportResponse {
    1: optional i32 deliveryChannelCode,       // 渠道
    2: optional double totalCost,              // 窗口内该渠道总花费
    3: optional double sales24hOrderMerchant,  // 以下 8 字段与改动 2 同口径（渠道级聚合）
    4: optional double sales24hOrderGoods,
    5: optional double sales24hDealMerchant,
    6: optional double sales24hDealGoods,
    7: optional double sales14dOrderMerchant,
    8: optional double sales14dOrderGoods,
    9: optional double sales14dDealMerchant,
    10: optional double sales14dDealGoods,
}

service OtdAgentToolService {
    // 【新增】广告主维度分渠道效果聚合查询
    AdvertiserChannelReportResponse getAdvertiserChannelReport(1: AdvertiserChannelReportQuery query),
}
```

**配套说明**：
- 渠道门槛计算口径：调用方按"同 ROI 口径"取对应销售额字段÷totalCost（如手动选 24h-下单-商家，则广告 ROI 与渠道门槛同用该口径）；
- 统计集合不随后续广告筛选改变（渠道内全部广告，含暂停/低消耗——如需排除规则请在响应或文档中说明，当前按全量聚合）；
- 周期上限 7 天与报表工具一致。

## 改动 6：我方 Agent 改动（专项计算工具+JSON 输出契约，非下游改动）

### 6.1 专项计算工具 `computePotentialCandidates`（新增 @Tool）

潜力识别的全部判定逻辑（STEP1/2/3）的**唯一宿主**——与 checkGoodsStatus 同构（输入实体→返回判定），规避工具膨胀（非简单封装）与字段污染（返回字段诊断工具不可见）：

- **入参**：`adIds`（初筛后广告 ID 列表，必填）+ `advertiserId`（必填）+ `metric`（指标 hardCode，必填，如 `ROI_14D_DEAL_GOODS`）；
- **内部行为**：批量拉取效果报表（customMetrics）+渠道大盘（getAdvertiserChannelReport）+离线快照限额（2300 分区 budget）→ Java 完成 STEP1（ROI≥门槛/上线≥7天/D5-D7日消耗≥100）+STEP2（分类型验证：智能=商品池≥10/单品=库存+oCPX二阶段/人群=人群包有效期）+STEP3（趋势忽略 D1 环比 D2-D4 vs D5-D7+排除[趋势下降/倍率<1.3]+双线建议档位）；
- **匹配**：以 adId 为唯一锚点 Map 键聚合（"LLM 是路由器不是 joiner"）；未关联到效果数据的广告按"无数据"进入缺失分支；
- **可选护栏**：入参 adIds 先经 getAdMeta(adIds) 复核（防幻觉传错 ID）；
- **返回**（工具专属字段）：`passed`（候选结果集，含每广告判定明细+建议档位）+`eliminated`（淘汰集+原因）+`processNotes`（step1Passed/step2Passed 漏斗计数）。

### 6.2 JSON 输出契约（前端自行渲染）

潜力计划识别结果以 **JSON 契约**输出，前端自行渲染机会卡片（不定长列表）：

- 契约标记：`<!--report-type:potential-plan-->`（与 `<!--report-type:diagnosis-->` 同构，前端按标记切片）；
- 契约区块互斥：一次回复至多一个契约区块（复用既有原则）；
- **JSON 骨架（精简定稿）**：

```json
{
  "reportType": "potential-plan",
  "dataRange": {"start": "yyyy-MM-dd", "end": "yyyy-MM-dd"},
  "metric": "ROI_14D_DEAL_GOODS",
  "candidateCount": 3,
  "scannedCount": 42,
  "emptyFallback": null,
  "processNotes": {"step1Passed": 8, "step2Passed": 5},
  "plans": [{
    "adId": "", "adTitle": "", "campaignId": "", "campaignTitle": "",
    "channel": 104, "channelName": "唯直达", "adType": "智能",
    "roi": 3.20, "channelThreshold": 2.00, "roiRatio": 1.60,
    "currentBid": 1.80, "dailyBudget": 600,
    "reason": "（build_reason 确定性模板生成，数值取自计算结果）",
    "suggestions": [
      {"type": "limit", "tier": "HIGH", "budget": 600},
      {"type": "bid", "tier": "T2", "bidPrice": 1.80}
    ],
    "trendData": {"actual": [0,0,0,0,0,0,0]}
  }]
}
```

- **字段口径**：`suggestions` 只给**档位类型+当前值**（limit tier=HIGH[利用率≥80%]/NORMAL[<80%]；bid tier=T1/T2/T3/T4）——百分比与目标值（+20%/+15%、+15%/18%/20%/25%、¥当前→¥目标）全由**前端按档位映射计算**（判定[分类]在我、展示[映射]在前端）；`budget`=预算、`bidPrice`=出价（与 AdMetaDTO 同名对齐）；
- **predicted 不给**（趋势图预估由前端按建议自行绘制或省略）；
- **0 推荐兜底**：`emptyFallback`（无候选时输出 `{title, content}` 兜底文版，前端渲染兜底卡片；常态缺省不输出 null）；
- **缺失即淘汰**：roiSalesMap 中指标 key 缺省（无数据）→ 该广告直接淘汰（无法执行 ROI 判定）。
